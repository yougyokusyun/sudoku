# 成语配图规格说明

- 版本：v1.0
- 日期：2026-11-06
- 状态：可评审（评审通过后作为成语类配图的唯一验收依据）
- 依据项目现状：`games/idioms.html`（成语闯关，24 个成语、47 处图片引用、24 个唯一文件）、`data/idioms-all.json`（成语大全 507 条，当前无配图）、`sw.js`（预缓存策略）

## 1. 适用范围

1. `games/idioms.html`「成语闯关」的猜一猜 / 填一填配图（现有 24 张，`games/img/idiom/`）。
2. `games/idioms-all.html`「成语大全」后续如增加配图，全部适用本规格。
3. 后续新增的同类语文配图页（成语、寓言、古诗意境图等）默认适用；与英文实景照片类页面（`games/img/sentences/`）不共用本规格，后者按 512×384 实景照片规范执行。

## 2. 尺寸与比例

| 版式 | 1x 像素 | 2x 像素（高 DPI） | 单张体积上限（1x / 2x） | 典型用途 |
| --- | --- | --- | --- | --- |
| 横版 4:3 | 512×384 | 1024×768 | ≤60 KB / ≤150 KB | 横版看图题（对齐现有英文图片规范） |
| 方版 1:1 | **640×640（推荐）** | **1280×1280（推荐）** | ≤80 KB / ≤200 KB | 成语闯关卡片、成语大全配图 |

推荐结论：**成语配图统一用方版 1:1，640×640（1x）+ 1280×1280（2x），实际发布优先只发一套 1280×1280 并压到 ≤200 KB**（单文件即可覆盖 1x/2x，减少仓库文件数）。

理由：
- 页面图片容器按 1:1 预留（`aspect-ratio: 1/1`），非 1:1 会被裁切，4:3 只适用于横版布局页面。
- 横屏 1024 宽时成语页为左图右题两栏，图列约占 44%（≈450 CSS px）；竖屏 768 宽时图区约 300 CSS px。640 短边在 1x 下足够，1280 覆盖 2x / 3x 平板。

iPad 最小可辨识要求：
- 图片显示短边 ≥ 240 CSS px；竖屏 768、横屏 1024 均在达标区间。
- 主体（人物/动物/关键道具）占画面 55%~70%，即主体短边 ≥ 120 CSS px（2x 下 ≥ 240 物理像素）。
- 禁止把 1x 图放大超过 1.1 倍显示；放大后主体短边不得低于 120 CSS px。

## 3. 格式与压缩

1. 格式优先级：**WebP（有损 q78）> JPEG（q82，progressive，兜底）> PNG（仅纯线稿）**。
2. WebP 参数：`cwebp -q 78 -m 6 -sharp_yuv`；带透明通道时 `-q 80 -alpha_q 90`。
3. JPEG 兜底参数：`cjpeg -quality 82 -progressive`；仅当目标环境不支持 WebP 时才保留 JPEG 版本。
4. 单张体积上限：
   - 横版 4:3：1x ≤60 KB，2x ≤150 KB；
   - 方版 1:1：1x ≤80 KB，2x ≤200 KB。
5. 取舍原则：先保主体轮廓、关键动作、色彩对比，再降纹理细节；宁可整体降噪，不可出现色块 / 锯齿 / 糊边；禁止用低分辨率图插值放大充当 2x；同一页面内同一档位图片的压缩参数必须一致。

## 4. 风格规范

| 项 | 规定值 |
| --- | --- |
| 画风 | 统一儿童水彩绘本风（与 v43 已重做的 24 张一致） |
| 背景 | 暖白纸感底 `#FBF3E4`，允许极淡纹理，不出现纯白死白或彩色渐变底 |
| 色调 | 低饱和，单图主要色相 ≤5 个；不用荧光色、强对比霓虹色 |
| 构图 | 正方形居中构图，主体居中偏下 5%；四周留白 ≥12%（640 图每边 ≥77 px） |
| 主体占比 | 55%~70%（过低不可辨识，过高无呼吸感） |
| 轮廓线 | 2.5~4 px @640，粗细在同一页面内统一；线色用深褐 `#5B4636`，不用纯黑 |
| 光源 | 统一左上 45°，阴影柔和、方向一致 |
| 人物 | 典故类穿素色古装，生活类穿现代童装；五官简化，不做写实人脸 |
| 禁止混用 | 同一页面不得同时出现水彩、扁平矢量、3D 渲染、照片、emoji 拼贴 |

## 5. 内容红线

1. 一眼能看出成语含义：只表现成语的字面情节（如「画蛇添足」必须出现“给蛇画脚”这个动作），不表现引申义、不做双关联想。
2. 不添加与成语无关的元素（现代物品、品牌、无关人物、装饰文字）。
3. 禁止 emoji 拼贴、表情符号替代主体。
4. 禁止任何文字：成语名、拼音、印章、落款、水印、logo、生成器水印、边框文字。
5. 禁止模糊、噪点、低分辨率、拉伸变形、主体被裁切。
6. 禁止恐怖、血腥、暴力、危险示范（如儿童玩火、攀爬高处）。
7. 一张图只对应一个成语，禁止一图多用。

## 6. 命名与目录

- 目录：`games/img/idiom/`
- 文件名：`<pinyin>.webp`
  - `pinyin` = 成语普通话拼音全拼，小写、无声调、无分隔符，`ü` 写作 `v`。
  - 例：画蛇添足 → `huashetianzu.webp`；守株待兔 → `shouzhudaitu.webp`。
  - 同成语多图变体：`<pinyin>-2.webp`、`<pinyin>-3.webp`，默认只用无后缀版本。
- 禁止用纯序号（`01.webp`）命名：序号无法与题库稳定对应，增删题会错位。
- 与题库字段对应：
  - `games/idioms.html` 每条题目对象的 `img` 字段存相对路径，如 `img: 'img/idiom/huashetianzu.webp'`（2026-11-06 已由 `.jpg` 统一迁移为 `.webp`）；
  - `data/idioms-all.json` 如增加配图，在条目中新增可选 `img` 字段（同相对路径规则），缺省则不显示图片；
  - 一个成语在题库中出现多次（猜一猜 / 填一填）时复用同一文件，不重复出图。

## 7. 授权与登记

可用授权档位：

| 档位 | 许可 | 可否进公开仓库 | 是否需署名 |
| --- | --- | --- | --- |
| A1 | CC0 | 可 | 否 |
| A2 | Public Domain (PD) | 可 | 否 |
| A3 | CC-BY / CC-BY-SA | 可 | 是（在 CREDITS 标注） |
| A4 | 自有 / 项目内 AI 生成 | 可 | 否（记为“项目自有”） |
| B | 来源不明、仅个人使用、NC / ND | **不可** | — |

登记文件：`games/img/idiom/CREDITS.md`（当前缺失，迁移时补齐）。逐张一行，字段固定为：

`| 文件名 | 成语 | 来源 URL | 作者 | 许可 | 是否需署名 | 入库日期 | 备注 |`

要求：
- 每张图必须有且只有一条记录，文件名与目录内文件一一对应；
- AI 生成图来源写“项目内生成”，作者写生成工具/流程名，许可记 A4；
- B 档素材只允许本地测试，不得提交到公开仓库。

## 8. 缓存策略

- 成语配图**不进 `sw.js` 的 `PRECACHE`**，只走运行时缓存。
- 理由：按 24 张 × 80 KB ≈ 1.9 MB，会把首装核心包（当前约 1.9 MB）直接翻倍，国内弱网下首装时间显著变长。
- 现状核对：`sw.js` 的 `PRECACHE` 中没有 `games/img/idiom/` 任何条目；仅 `img/words/index.json` 与 icon 入列，成语图符合策略。
- 运行时缓存条件保持：同源 GET、`response.ok`、type 为 basic/default 才 `cache.put`；打开过的图自动落地。

## 9. 生成与审核流程

1. 生成：1280×1280，每成语出 3 张候选；提示词限定“儿童水彩绘本风、无文字、字面情节”。
2. 后处理：去水印 → 统一色调与背景 `#FBF3E4` → 裁切 1:1（主体居中）→ 轮廓线统一。
3. 可辨识度盲测：找 5 名未看过题目的人（建议 3 名儿童 + 2 名成人），只看图、5 秒内说出成语；**≥4/5 答对才通过**，3/5 退回重做，≤2/5 直接废弃。
4. 压缩：按第 3 节参数转码，超上限则降 q 值（每次 -4），仍超则缩到 640 发布。
5. 入库：写入 `CREDITS.md`，同步题库 `img` 字段，跑一次 1024×768 与 768×1024 显示检查（无横向滚动、无裁切变形）。
6. 抽检：每批随机抽 20% 图做人工复核，重点看文字残留与水印。

## 10. 验收清单

- [ ] 尺寸：方版 640×640 或 1280×1280（比例误差 0），横版 512×384 或 1024×768
- [ ] 格式：WebP（JPEG 仅作兜底，且成对存在）
- [ ] 体积：1x ≤80 KB / 2x ≤200 KB（横版 ≤60 KB / ≤150 KB）
- [ ] 画风：与同页其它图一致，无照片 / 3D / emoji 拼贴混入
- [ ] 无文字、无印章、无水印、无 logo、无生成器标记
- [ ] 可辨识度：盲测 ≥4/5 在 5 秒内说对成语
- [ ] 构图：主体占 55%~70%，四边留白 ≥12%，无裁切变形
- [ ] CREDITS：每张图一行，字段齐全，许可为 A 档
- [ ] 命名：`<pinyin>.webp` 全拼小写，题库 `img` 字段可对应
- [ ] 外部引用为 0：页面 `<img src>` 全部为站内相对路径
- [ ] 缓存：未加入 `sw.js` PRECACHE
- [ ] 两视口：1024×768 与 768×1024 无横向滚动、图不变形

## 11. 现状对照与迁移建议

现状盘点（2026-11-06，`games/img/idiom/`）：

- 24 个文件，全部 `.jpg`；
- 尺寸全部 900×900；
- 体积 73,237 ~ 207,941 B，平均 125,382 B，合计 2.87 MB；
- 题库引用 47 处（猜一猜 + 填一填共用 24 个唯一文件）；
- `idioms-all.html` / `data/idioms-all.json` 当前无配图；
- 无 `CREDITS.md`；
- 未进 `PRECACHE`。

逐项对照：

| 项 | 本规范 | 现状 | 结论 |
| --- | --- | --- | --- |
| 格式 | WebP q78 | JPEG 24/24 | 不符，需转码 |
| 尺寸 | 640 或 1280（1:1） | 900×900 | 介于两档，可视为 1.4x；保留可接受，新图按 1280 |
| 体积（按 1x ≤80 KB） | ≤80 KB | 23/24 超 80 KB | 不符 |
| 体积（按 2x ≤200 KB） | ≤200 KB | 1/24 超 200 KB（`yegonghaolong.jpg` 207,941 B） | 基本符合 |

迁移建议（成本低、收益明确，建议执行）：

1. 需重做张数：**0 张**（画面沿用，不重新生成）。
2. 需转码：24 张，`cwebp -q 78`，目标 900×900 保留或统一缩到 1280 以内；预计总体积 2.87 MB → **约 1.0~1.3 MB**，节省 1.6~1.9 MB。
3. 需改引用：`games/idioms.html` 47 处 `img/idiom/*.jpg` → `*.webp`（24 个唯一文件）。
4. 需补登记：`games/img/idiom/CREDITS.md` 新增 24 行（AI 生成记 A4 项目自有）。
5. 人工复核：24 张逐张看文字残留与水印，抽查 1024×768 / 768×1024 显示。
6. 工作量评估：一次性半天内可完成；优先级 P1 转码 → P2 引用替换 → P3 CREDITS 补齐。
7. 结论：**值得迁移**（体积降约 60%，格式与体积极限达标；无需重画，风险集中在引用替换，需一次全站 404 检查）。
